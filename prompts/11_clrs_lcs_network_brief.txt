## Your task

Write the weights of a looped transformer that executes one algorithm of the CLRS-Text benchmark,
`lcs_length` (LCS-LENGTH of CLRS (Cormen et al.), section 15.4). Nothing is trained: every weight is written by code you write.

**The problem.** The input is two sequences, `string` and `key`, over a small alphabet. The output `b` is the table of the longest-common-subsequence dynamic program: for every cell, the direction its value came from, in the form and with the conventions the dataset uses.

**Input.** Each problem is one text prompt, exactly as the CLRS-Text dataset gives it to a language model. It starts
with `lcs_length:`, then the inputs and the algorithm's `initial_trace`, and ends with the line `trace | b:`.
The DEV prompts show the exact format. The number of nodes or the sequence length is one of 4, 5 and 10.

**Output.** The final output `b` in the dataset's format, for example `[0 1 2 0 1]`. You may first write the
execution trace and `|`, as the dataset's answers do, or write only the final output.

**Scoring:** per problem, solved or not (`tools/grader.py`).
- The final output of a response is the text after its last `|` (the whole text if there is none), with lines starting
  with three backticks dropped and whitespace stripped at both ends.
- It must equal the problem's final output exactly. Anything else scores 0.
- The TEST score is the fraction solved.

**TEST** is this algorithm's problems in the five CLRS-Text test splits (test_1 to test_5), new random problems of the
same kind and sizes as DEV. You never see TEST. When you say you are done, the orchestrator freezes your files and runs
TEST on a GPU with the runner's `torch64` path (float64).

## Data in your folder

- `dev/dev_lcs_length.jsonl`: 1,000 problems from the CLRS-Text train split, an equal number per size. Each line is
  `{"id", "prompt", "answer", "size"}`, where `answer` is the final output.

You may analyse the DEV inputs and answers with any code you like, as often as you like. The dataset's conventions
(ids, ties, unreachable nodes, number formats) are for you to work out from DEV.

## The frame (fixed; implemented in `runner/`, described in `runner/README.md`)

Inference is the generic loop: embed → the same block R times → readout.

- **Input.** The network reads exactly the prompt text, character for character. Nothing is removed, added or
  reformatted.
- **Tokenizer.** You write it in `tokenizer.py` and declare it. It maps a text string to a sequence of tokens, each a
  tuple of non-negative integer fields, each below the size of its embedding table.
  - It must work unchanged on any text.
  - It must know nothing about graphs, matrices, sequences, this algorithm or the question format.
  - The auditor checks both.
- **Embedding.** The sum of one table per token field.
- **Block.** A fixed list of layers, the same in every loop. Each layer does
  `h ← h + Σ_heads softmax(Q Kᵀ/√d_k + mask) V W_O`, then `h ← h + W2 ReLU(W1 h + b1) + b2`.
  - The mask is none or causal, per head.
  - There is no normalisation.
  - The widths and the numbers of layers and heads are yours to choose.
- **Loops.** R comes from a rule you declare that depends only on the number of tokens n (see `runner/README.md`).
- **Readout.** A linear map at every position, then argmax over an output alphabet you declare: a list of strings,
  one of which is the empty string.
  - Each position writes one alphabet string, or nothing (the empty string).
  - The answer is the written strings in position order.
  - The harness passes that string to the grader unchanged, with nothing added. Your network must write everything
    the grader needs.
- **Arithmetic.** The runner has these paths (`runner/README.md`): `numpy` (float64) and `numpy32` (float32) on this
  machine; `torch32` and `torch64` on a GPU. DEV runs use `numpy` or `numpy32`, as you choose. TEST uses `torch64`. The
  written answer must be the same on `numpy` and `torch64`.
- **Compute limit.** At most 1 × 10¹⁴ FLOPs per prompt, counted by the runner from your shapes before it runs
  (`runner/flops.py`). The runner refuses any prompt over the limit.

## Rules

1. No training, gradients or fitting weights to data. Every weight is written by your code.
2. Inference is the generic loop above, with no task logic in Python, the tokenizer or the readout. Python only
   tokenizes, runs embed → block R times → readout, and joins the written strings. The tokenizer is generic and
   declared.
3. **DEV budget: 20 runs.** A run is any evaluation of your network on official DEV problems, on any number of them.
   - Running your network on anything built from a DEV problem (a part of one, an edited copy, its inputs or its
     answer) also counts as a DEV run.
   - Runs on inputs you make yourself do not count. Such inputs may reuse the prompt format, but no inputs or answer
     from the DEV file.
   - Run your network on DEV, or on inputs built from DEV, only through `tools/dev_run.py` (`--from-dev` for inputs
     built from DEV), which counts each run in `ledger/`. Do not edit the ledger; the auditor checks it against your
     transcript.
4. **No GPU runs.** This machine has no GPU, and this build has no GPU runs: every DEV run is on this machine.
5. **Time limit:** 12 hours of working time. Time paused by a usage limit doesn't count, and the orchestrator logs each
   pause.
6. TEST is never shown to you. Do not look for it or for any other copy of CLRS-Text or CLRS.
7. **Isolation.**
   - Work only inside this folder: do not read, list or look through anything outside it.
   - No web or network access of any kind: no web queries, no page fetches, no `curl`, `wget`, `pip`, `ssh`, `git`
     remotes, Hugging Face or GitHub.
   - Some of this is blocked by your permissions. The rest is a rule, and your transcript is checked afterwards.
8. During the build you will receive only: "continue", how much DEV budget is left, and answers to questions about
   these rules. Design questions get "that's your call."
9. If you find a problem with the rules, the data or the frame, stop and say so rather than working around it.
